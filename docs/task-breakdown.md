# 可并行任务详单

> 目标：把一期任务拆成多个可以并行推进的子任务包，便于快速协作和迭代。

---

## 0. 任务分级说明

- **P0**：必须先落地的底座
- **P1**：采集主链路
- **P2**：下载与分析链路
- **P3**：增强与优化

---

## P0：项目底座

## T0-1 配置体系

### 目标

建立统一配置管理，支持 Windows / Ubuntu 迁移。

### 输出

- `config.yaml.example`
- 配置读取模块
- 路径 / 浏览器 / 下载 / 数据目录配置

### 可并行

是

### 前置依赖

无

### 验收标准

- CLI 能读取配置
- 路径可切换

---

## T0-2 数据库表结构与 ORM

### 目标

把核心表建起来。

### 输出

- ORM 模型
- migration 初始化
- SQLite 可创建

### 可并行

是

### 前置依赖

无

### 验收标准

- 本地数据库可初始化
- 表结构齐全

---

## T0-3 主页列表导入器

### 目标

支持导入多个主页 URL 及分类属性。

### 输入

- CSV / JSON

### 输出

- `homepage_targets`

### 可并行

是

### 前置依赖

- T0-2

### 验收标准

- 成功导入 20 个以内主页
- 分类属性正常入库

---

## P1：会话与采集主链路

## T1-1 Playwright 会话管理

### 目标

实现 storage state 加载与保存。

### 输出

- `session-login` CLI
- state 文件管理
- 登录有效性检测

### 可并行

是

### 前置依赖

- T0-1

### 人工配合点

- 首次登录
- 验证码处理

### 验收标准

- 可人工登录一次并保存会话
- 后续启动可复用

---

## T1-2 主页采集器

### 目标

给定主页 URL，发现主页视频列表。

### 输出

- 视频 URL
- video_id
- 发布时间
- 封面 / 标题（若可得）

### 可并行

部分可并行

### 前置依赖

- T1-1
- T0-2

### 验收标准

- 对一个主页可抓到作品列表
- 能翻动并获取多条视频

---

## T1-3 视频详情采集器

### 目标

进入视频页抓取互动数。

### 输出

- `video_snapshots`

### 可并行

是

### 前置依赖

- T1-2

### 验收标准

- 可记录播放 / 点赞 / 评论 / 转发
- 写入快照表

---

## T1-4 评论采集器

### 目标

尽量抓评论与回复，并显式记录完整性。

### 输出

- `comments`
- `comment_replies`
- `comment_scan_runs`

### 可并行

是

### 前置依赖

- T1-3

### 人工配合点

- 某些视频需人工过验证

### 验收标准

- 至少能抓首层评论
- 能抓一部分回复
- incomplete 状态可记录

---

## T1-5 原始产物归档

### 目标

为异常复盘保留 HTML / JSON / screenshot。

### 输出

- `artifacts`
- 存储工具类

### 可并行

是

### 前置依赖

- T0-2

### 验收标准

- 采集失败时能保留现场文件

---

## P2：下载与媒体处理

是

- T1-2

### 可并行

### 前置依赖

- T2-1

### 验收标准

---

## T2-4 媒体资产校验与入库

### 可并行

是

### 前置依赖

- T2-2 或 T2-3

### 验收标准

## 10. 推荐执行顺序

### 第一批并行

- T0-1 配置体系
- T0-2 数据库与 ORM
- T1-1 Playwright 会话管理

### 第二批并行

- T0-3 主页导入器
- T1-2 主页采集器
- T1-5 原始产物归档

### 第三批并行

- T1-3 视频详情采集器
- T2-1 下载任务生成器

### 第四批并行

- T1-4 评论采集器
- T2-2 下载器适配
- T2-3 yt-dlp 兜底

### 第五批并行

- T2-4 媒体资产入库
- T2-5 抽帧与镜头切分
- T2-9 音频抽取

### 第六批并行

- T2-6 画面质量分析
- T2-7 人脸分析
- T2-8 姿态分析
- T2-10 ASR

### 第七批并行

- T2-11 话术结构分析
- T3-1 调度器
- T3-2 状态报表 CLI

---

## 11. 我建议的近期实际推进顺序

为了最快拿到成果，我建议我们下一步开发顺序是：

1. T0-1 配置体系
2. T0-2 数据库与 ORM
3. T0-3 主页导入器
4. T1-1 Playwright 会话管理
5. T1-2 主页采集器
6. T1-3 视频详情采集器
7. T1-4 评论采集器
8. T2-1 / T2-2 / T2-3 下载链路

等这 8 个落地后，系统就已经从“方案”进入“可运行采集系统”阶段了。
